# 4. 시연 시나리오

Galaxy S10으로 작업을 촬영하고, EC2 서버에 올려 학습용 데이터로 정제되는 것까지 보여 준다. 마지막으로 GPU 서버의 학습·시뮬레이션 결과를 보여 준다.

## 사전 준비

| 항목 | 확인 |
|---|---|
| S10 | TIGER MASK 앱 설치 (`tigerUploadBaseUrl` 을 넣고 빌드한 APK), Google Play Services for AR 최신, Wi-Fi 연결 |
| 거치 | 폰을 그리퍼 거치대에 가로로 고정 |
| 조명 | 밝게. 어두우면 ARCore가 `INSUFFICIENT_LIGHT` 로 Tracking을 못 잡아 작업 구간을 시작할 수 없다 |
| EC2 | `curl http://<EC2>/health` → `{"status":"ok","service":"ingestion"}` |
| 관리자 PC | EC2 SSH 터미널 1개, GPU 서버 SSH 터미널 1개 |
| 시연 물체 | 공 1개, 바구니 1개 (시뮬레이션과 같은 pick-and-place 작업) |

앱은 세로 고정이고, 수집 화면만 가로로 바뀐다.

## 1장. 앱 실행과 Task 목록

| # | 화면 | 동작 (위치) | 결과 |

기존 Task에 이어서 찍으려면 Task 카드를 눌러 세션 목록으로 들어간 뒤 같은 FAB를 누른다. 그러면 Task 이름이 미리 채워진다.

## 3장. 카메라 설정 (MASK)

같은 광학 조건으로 찍는다는 점을 보여 주는 장이다. 이 장은 세션 시작 전에만 할 수 있다.

| # | 화면 | 동작 (위치) | 결과 |
|---|---|---|---|
| 3-1 | 수집 화면 | **좌측 상단 톱니바퀴** 탭 | 오른쪽에서 "카메라 설정" 시트가 열린다. 프리뷰는 어두워지지 않는다 |
| 3-2 | 카메라 설정 | **녹화 해상도** `1920×1080` 선택 | |
| 3-3 | 〃 | **초점** 슬라이더를 NEAR 쪽으로 이동 | 가까운 물체가 즉시 선명해진다 |
| 3-4 | 〃 | **ISO** 슬라이더, **셔터** `1/60` 선택 | 프리뷰 밝기가 바로 바뀐다. "FPS 30 고정" 표시 |
| 3-5 | 〃 | **화이트 밸런스 "현재 값으로 고정"** 탭 | 상태가 "고정됨"으로 바뀐다 |
| 3-6 | 〃 | 시트의 **✕** 탭 | 시트가 닫힌다. 값은 저장돼 다음 실행에도 남는다 |

설명할 점: 자동으로 두면 10초 동안 노출 설정이 74번 바뀌고, 수동으로 고정하면 0번 바뀐다.

## 4장. 세션 녹화와 작업 구간(Episode)

제어 버튼은 **화면 오른쪽 가장자리 가운데**에 세로로 있다.

| # | 상태 배지 (좌측 상단) | 동작 | 결과 |
|---|---|---|---|
| 4-1 | — (톱니바퀴 자리) | **▶ 세션 시작** (초록) 탭 | 녹화가 시작되고 톱니바퀴가 사라진다. 카메라 설정은 잠긴다 |
| 4-2 | **INITIALIZING · ARCore Tracking 준비 중** | 폰을 천천히 좌우로 움직인다 | Tracking이 잡히면 **READY** 로 바뀐다 |
| 4-3 | READY | **▶ 작업 구간 시작** 탭 | **EPISODE ACTIVE**. 공을 집어 바구니에 넣는 동작을 한다 |
| 4-4 | EPISODE ACTIVE | **Ⅱ 작업 구간 일시 정지** 탭 | Episode가 끝나고 READY로 돌아온다 |
| 4-5 | READY | 4-3 ~ 4-4를 한두 번 더 반복 | Episode가 여러 개 쌓인다 |
| 4-6 | READY | **■ 세션 종료** (빨강) 탭 | "세션을 종료할까요?" 확인 창 |
| 4-7 | 확인 창 | **종료** 탭 | **FINALIZING**. 화면 전체에 "세션을 마무리하고 있습니다 / 저장이 끝날 때까지 앱을 닫지 마세요." |

주의할 점:

- READY가 되기 전에 ▶을 누르면 "ARCore Tracking이 안정화되면 작업 구간을 시작할 수 있습니다."가 뜬다.
- EPISODE ACTIVE 중에 ■를 누르면 "ACTIVE Episode를 먼저 END 또는 CANCEL 하세요."가 뜬다. 반드시 Ⅱ를 먼저 누른다.
- Episode 도중 Tracking이 끊기면 그 구간은 무효로 끝난다. "Tracking이 끊겨 현재 작업 구간을 무효로 종료했습니다. 세션은 계속됩니다."
- FINALIZING 중에는 앱을 백그라운드로 보내지 않는다. 진행 중인 세션이 INTERRUPTED로 마감된다.

## 6장. CPU 서버에서 수신·정제 확인 (EC2 터미널)

앱에서 5-2의 ID를 보고 같은 세션을 찾는다.

```bash
ls /srv/sessions/<session_id>/
# metadata.json main_rgb.mp4 main_frame_timestamps.csv arcore_poses.csv episodes.csv
# accelerometer.csv gyroscope.csv rotation_vector.csv

cd /home/ubuntu/server
./.venv/bin/python preprocess.py --session-id <session_id>

ls /srv/processed/v1/<session_id>/
# session_metadata.json  episode_<id>/ ...  READY
cat /srv/processed/v1/<session_id>/episode_*/quality.json
```

설명할 점:

- 업로드 파일 8개가 SHA-256까지 검증된 뒤 원자적으로 저장된다.
- 같은 세션을 다시 보내면 `200 duplicate` 가 나오고 새로 저장하지 않는다.
- `READY` 파일은 학습에 쓸 수 있는 segment가 하나 이상일 때만 생긴다. Tracking이 끊긴 구간은 짧으면 보간하고, 길면 segment를 나눈다.

## 7장. GPU 서버 학습·평가 (GPU 서버 터미널)

```bash
cd ~/universal_manipulation_interface      # gpu_server/omx-umi-sim
./scripts/sync_processed_from_cpu.sh       # READY 세션만 가져온다
python scripts/inspect_synced_processed.py # DATASET STATUS 출력
python -m omx.cli build   omx_pick_raw_center_v1
python -m omx.cli inspect omx_pick_raw_center_v1
```

학습 전체는 시연 시간 안에 끝나지 않는다. 미리 돌려 둔 결과를 보여 준다.

| 보여 줄 것 | 위치 |
|---|---|
| MuJoCo 폐루프 평가 영상 (G0 기준선, Ablation B) | `gpu_server/omx-umi-sim/MEDIA.md` 에 나열된 영상 |
| 결과 표 | `gpu_server/omx-umi-sim/RESULTS.md` |

요점: G0 기준선은 10번 중 8번 공을 들고, 2번 바구니에 넣는다. Ablation B(oracle relation FiLM)는 확실한 파지 6/10, 바구니 4/10으로 같은 평가기의 G0 대조군(3/10, 2/10)보다 높다. 팔마다 n = 10이라 유의성은 주장하지 않는다.
