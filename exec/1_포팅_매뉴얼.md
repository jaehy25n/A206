# 1. 포팅 매뉴얼

GitLab 저장소(`S15P21A206`)를 클론한 뒤 각 구성 요소를 빌드하고 배포하는 절차다.

## 0. 시스템 구성

```text
Galaxy S10 (Tiger 앱)
    │  POST /sessions  (multipart, HTTP 80)
    ▼
EC2 CPU 서버 (cpu_server)      nginx :80 → uvicorn(FastAPI) 127.0.0.1:8000
    │  /srv/sessions → preprocess.py → /srv/processed/v1/<session>/READY
    │  rsync over SSH (GPU가 pull)
    ▼
GPU 서버 (gpu_server)          processed_v1 → UMI Zarr → Diffusion Policy 학습
    │  체크포인트 / handoff 번들
    ▼
Jetson (로봇 제어기)            추론
```

| 디렉터리 | 구성 요소 | 언어·런타임 |
|---|---|---|
| `Tiger/` | Android 수집 앱 (TIGER MASK) | Kotlin, Gradle |
| `cpu_server/` | 업로드 수신·전처리 서버 | Python 3.12, FastAPI, nginx |
| `gpu_server/omx-umi-sim/` | 학습·시뮬레이션·평가 | Python 3.9 / 3.12, PyTorch, MuJoCo, ROS 2 |
| `camera_matching/` | S10 ↔ LUAZ 카메라 캘리브레이션 도구 | Python 3.11 |
| `3d모델/` | 그리퍼 STEP 파일 | — |

### 클론할 때 주의 (Windows)

`gpu_server/omx-umi-sim/sim_umi/scripts/aux/` 는 Windows 예약어(`aux`)라 Windows에서 체크아웃되지 않는다. GPU 서버(Linux)에서는 그대로 클론하면 된다. Windows에서 받아야 하면 그 폴더만 빼고 받는다.

```bash
cd S15P21A206
```

## 2. 빌드

### 2-1. Android 앱

`Tiger/local.properties` 에 업로드 서버 주소를 넣는다. 이 파일은 `.gitignore` 대상이라 저장소에 없다.

```properties
sdk.dir=C\:\\Users\\<사용자>\\AppData\\Local\\Android\\Sdk
tigerUploadBaseUrl=http://<EC2_퍼블릭_주소>
```

```powershell
cd Tiger
.\gradlew.bat assembleDebug          # → app/build/outputs/apk/debug/app-debug.apk
.\gradlew.bat testDebugUnitTest      # 단위 테스트
.\gradlew.bat lintDebug
```

설치: `adb install -r app/build/outputs/apk/debug/app-debug.apk`, 또는 Android Studio에서 Run.

### 2-2. CPU 서버

빌드 단계는 없다. 가상환경을 만들고 의존성만 설치한다. 3장 배포 절차에 포함했다.

### 2-3. GPU 서버

```bash
cd gpu_server/omx-umi-sim
bash colab/setup_colab.sh        # micromamba → ./.mamba/envs/omx (Python 3.9) + env/requirements-train.txt
source colab/activate.sh         # PATH, MUJOCO_GL=egl, PYTHONNOUSERSITE=1
python -m omx.cli env            # GPU·정밀도·wandb 버전 점검
```

conda를 쓰면 `mamba env create -f env/environment-train.yml` (호스트와 바이트 단위로 같게 하려면 `umi_working_env.yml`).

시뮬레이터 env와 C++ overlay 빌드는 `gpu_server/omx-umi-sim/ENVIRONMENT.md` 3절을 따른다.

```bash
micromamba create -f env/environment-sim-ros.yml && micromamba activate omx_ros
bash external/mujoco_ros2_control/build/build_overlay.sh         # ~/omx_overlay
bash external/mujoco_ros2_control/build/build_overlay_masks.sh   # ~/omx_overlay_masks (mask 평가기용)
```

## 4. 배포

### 4-1. CPU 서버 (EC2)

```bash
sudo apt update && sudo apt install -y python3-venv ffmpeg nginx

sudo mkdir -p /home/ubuntu/server && sudo chown ubuntu:ubuntu /home/ubuntu/server
cp -r cpu_server/server/. /home/ubuntu/server/
cd /home/ubuntu/server
python3 -m venv .venv && ./.venv/bin/pip install -r <repo>/cpu_server/requirements.txt

# 런타임 디렉터리. 애플리케이션이 만들지 않으므로 반드시 먼저 만든다
sudo mkdir -p /srv/incoming /srv/sessions /srv/locks /srv/processed/v1
sudo chown ubuntu:ubuntu /srv/incoming /srv/sessions /srv/locks /srv/processed/v1

sudo cp <repo>/cpu_server/deploy/server.service /etc/systemd/system/server.service
sudo systemctl daemon-reload && sudo systemctl enable --now server

sudo cp <repo>/cpu_server/deploy/nginx-server.conf /etc/nginx/sites-available/server
sudo ln -sf /etc/nginx/sites-available/server /etc/nginx/sites-enabled/server
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx

curl -s http://127.0.0.1:8000/health    # {"status":"ok","service":"ingestion"}
```

전처리는 서비스가 아니라 수동 배치다.

```bash
cd /home/ubuntu/server
./.venv/bin/python preprocess.py                         # 전체 세션
./.venv/bin/python preprocess.py --session-id <uuid>     # 한 세션
./.venv/bin/python preprocess.py --force --session-id <uuid>   # 기존 출력 교체
```

### 4-2. GPU 서버

```bash
ssh-keygen -t ed25519 -f ~/.ssh/tiger_cpu_sync
cat ~/.ssh/tiger_cpu_sync.pub                 # EC2 ubuntu 계정의 authorized_keys에 등록
```

## 5. 배포 시 특이사항

**CPU 서버**

- 경로가 하드코딩돼 있다: `main.py`의 `ROOT = Path("/srv")`, systemd unit의 `/home/ubuntu/server`. 다른 경로에 두려면 둘 다 고친다.
- `/srv/incoming` 과 `/srv/sessions` 는 같은 파일시스템이어야 한다. 원자적 `rename()`이라 다른 마운트면 `EXDEV`로 실패한다.
- nginx 기본 사이트(`sites-enabled/default`)를 지워야 한다. 남아 있으면 업로드가 기본 사이트로 간다.
- 대용량 업로드 설정: `client_max_body_size 20G`, `client_body_timeout`·`proxy_read/send_timeout 3600s`, `proxy_request_buffering off`.
- 인증이 없고 80 포트 평문이다. 보안그룹에서 접근 IP를 제한한다. 공개망에 노출하려면 TLS와 인증을 앞에 둔다.
- rsync는 삭제를 전파하지 않는다. CPU에서 재처리 후 READY가 사라진 세션은 GPU에서 직접 지운다.

**Android 앱**

- ARCore 지원 기기와 최신 Google Play Services for AR가 필요하다. 매니페스트가 `com.google.ar.core=required` 다.
- 업로드 서버가 HTTP라 `usesCleartextTraffic="true"` 로 빌드된다.
- `tigerUploadBaseUrl` 을 넣지 않고 빌드하면 업로드 버튼이 "업로드 서버 주소가 설정되지 않았습니다."로 막힌다.
- MASK 없는 기존 Tiger와 applicationId가 달라 한 기기에 함께 설치된다.

**GPU 서버**

- 러너 스크립트, `sim_umi/ros/env_overlay.sh`, URDF의 `<mujoco_model>` 에 `/home/j-j15a206/...` 경로가 박혀 있다. 그 경로로 클론하거나 심볼릭 링크를 만든다.
  `mkdir -p /home/j-j15a206 && ln -s <repo>/gpu_server/omx-umi-sim /home/j-j15a206/universal_manipulation_interface`
- 학습과 폐루프 평가를 같은 GPU에서 동시에 돌리지 않는다.
- V100은 bf16이 없다. 기본 fp32, `mixed_precision="fp16"`만 선택적으로 쓴다.
- wandb 0.22.3 미만은 86자 API 키를 거부한다.
- 데이터셋과 체크포인트는 저장소에 없다. `manifests/*_sha256.txt` 로 대조해서 넣는다.
