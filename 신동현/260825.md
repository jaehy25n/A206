코드를 살펴본 결과, 문제가 있을 여지로 보이는 코드는 단 2군데 였다.

      float mag = sqrt(
          sx * sx +

      );

      float theta =
          atan2(sy, sx) *

현재 640 * 480 해상도에서 작업 중이기 때문에, 이 계산을 약 30만 번 반복하게 되는 것이다.

단순하게 봐도 + - * 같은 하드웨어 단에서 연산이 가능하지 않은 sqrt나 atan2가 들어간 것이 문제가 될 것 같았다.

그래서, 해당 값들을 연산을 안하는 하드코딩 값으로 변경 후 latency를 확인해 봤다

-> 아무튼 Gradient만 보면 된다.

sqrt 변환은 크게 영향이 없었다

으로, 기존 sqrt를 복원하고 theta 값만 하드코딩으로 바꿔보았다.

Mean FPS : 47.95 30 FPS budget: 33.33 ms / frame P95 status : PASS (25.04 ms)

마찬가지로, Gradient 이후는 하드코딩의 영향으로 신뢰성을 얻을 수 있는 지표는 아니다. 하지만 Gradient에서 atan을 하드코딩 한다고 지연에서 이상 이득이 생기진 않으므로 최소한 10.30ms - 1.78ms = 약 8.52ms 의 이득을 봤다고 할 수 있다.

즉, Gradient의 현재 가장 큰 병목은 atan2()가 맞았다.
Gradient에서의 연산을 보면, 앞선 Sobel에서 계산한 각 픽셀에 대한 x/y축 변화량을 vector 관점에서 보고 어느 방향으로의 변화량이 큰 지를 파악하기 위해서

각축의 변화량을 만족하는 세타값을 얻어내고자 한다. 이 과정에서

theta = atan2(gy, gx);

를 사용한다.

하지만 arctan은 덧셈이나 곱셈과 같이 소수의 기본 산술 연산만으로 정확한 결과를 바로 얻을 수 있는 연산이 아니라 초월함수이다.

따라서 당연하게도일반적인 CPU에서는 atan2 하나에 대응하는 단순한 산술 명령 하나로 처리되지 않고, 수학 라이브러리 내부에서 입력 범위를 조정하고 근삿값을 계산한 뒤 사분면에 따른 보정을 수행하는 식으로 구현된다.

즉 현재 코드는 약 30만 개의 픽셀 각각에 대해 정확한 Gradient 각도를 계산하고 있는 셈이다.

그러나 Canny의 다음 단계인 NMS에서는 이 정확한 각도를 그대로 사용하지 않는다

계산된 각도는 결국

0°
45°
90°
135°
네 방향 중 하나로 다시 분류된다.

예를 들어 38.7°라는 값을 계산하더라도 NMS에서는 결국 45° 방향으로 사용된다.

따라서

Gx, Gy → atan2() → 정확한 angle 계산 → 4방향 Quantization

과정을 거칠 필요 없이,

Gx, Gy → 크기 관계와 부호 비교 → 바로 4방향 Quantization

하는 방식으로 변경할 수 있을 것으로 판단했다.

이를 단순화하기 위해 정확한 theta 값을 구할 필요 없이, 이미 가지고 있는 Gx, Gy의 비율 관계를 이용해 Gradient 방향을 직접 분류할 수 있다.

기존에는

theta = atan2(gy, gx);

를 통해 정확한 각도를 계산한 뒤, NMS에서 다시 해당 각도를 0°, 45°, 90°, 135°의 4개 방향으로 분류했다.

하지만 실제 NMS에서 필요한 것은 정확한 각도 자체가 아니라 어느 방향의 이웃 픽셀과 magnitude를 비교해야 하는지에 대한 정보뿐이다.

각 방향의 경계는 기존과 동일하게 22.5°, 67.5°를 기준으로 잡을 수 있다.

Gradient vector에 대해

tan(theta) = |Gy| / |Gx|

이므로,

tan(22.5°) ≈ 0.4142 tan(67.5°) ≈ 2.4142

를 이용하면 다음과 같이 방향을 분류할 수 있다.

|Gy| / |Gx| < 0.4142 → 0°

|Gy| / |Gx| > 2.4142 → 90°

그 사이 → 45° 또는 135°

대각선 방향인 45°와 135°는 Gx, Gy의 부호 관계를 이용해 구분한다.

Gx, Gy의 부호가 같음 → 45°

Gx, Gy의 부호가 다름 → 135°

또한 실제 구현에서는 매 픽셀마다 |Gy| / |Gx| 나눗셈을 수행할 필요도 없다.

|Gy| / |Gx| < 0.4142

는

|Gy| < 0.4142 * |Gx|

와 동일하므로, 나눗셈 없이 곱셈과 비교 연산만으로 방향을 결정할 수 있다.

결과적으로 기존의

Gx, Gy → atan2() → 정확한 theta 계산 → degree 변환 → 4방향 Quantization

과정을

Gx, Gy → 절댓값 및 부호 비교 → 4방향 Quantization 으로 변경할 수 있었다.
