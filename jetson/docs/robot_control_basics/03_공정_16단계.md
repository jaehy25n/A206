# 03. 공정 — 빈 레포에서 동작하는 태스크까지 16단계

각 단계의 존재 이유는 **무엇을 증명하는가**. 증명하는 게 없으면 순서가 틀렸거나 단계가 아니다.
원칙: 각 단계는 다음 단계가 의존하기 전에 검증 가능해야 하고, 싸고 안전한 단계가 비싸고 위험한 단계보다 먼저.

| # | 단계 | 증명하는 것 | 건너뛰기? |
|---|---|---|---|
| 1 | **기반 고정** — 우분투/ROS/JetPack을 적고 그걸로 베이스 이미지 선택, 외부 레포 SHA 고정 | 이후 모든 실패가 *apt의 변화*가 아니라 *내 변화*. 없으면 "3월 버그를 9월에 재현" 불가 | ✗ (1시간) |
| 2 | **호스트 디바이스·전송 배관** — USB 시리얼 번호 기준 udev SYMLINK, `latency_timer=1`, compose 권한, RMW/DOMAIN_ID 통일, `rmw_zenohd` | 디바이스 경로와 전송이 **상수** → 디스커버리 실패를 로직 실패로 오해 불가. FTDI 기본 16 ms latency_timer만으로 ~60 Hz 상한 | ✗ |
| 3 | **물리 정지 + 버스 소유 규칙** — DC 급전에 래칭 e-stop, `/dev/ttyACM0` 단일 소유 규칙 문서화 + 사전 점검 명령, 토크 사이클 허용 park 포즈 정의 | 소프트웨어가 먹통이어도 팔을 세운다. 반이중 충돌이 *미스터리*에서 *절차 위반*으로 강등. (ISO 13850: 전원 차단만 e-stop, ROS로 쓰는 건 전부 "정지 요청") | ✗ 통전 동작 전 필수 |
| 4 | **서보를 읽고 한계값 출처를 하나로** — 읽기 전용 프로브, 그 표에서 URDF `<limit>`과 SW 한계를 **생성** | ID↔관절, tick↔rad, 세 출처 중 **누가 실제로 모터를 멈추는지**. 안 움직이니 공짜 | ✗ |
| 5 | **로봇 기술 + 4단 검증** — xacro 전개 → `check_urdf` → `urdf_to_graphiz` → RSP + slider + RViz | 문법 → 위상 → 기하 → **부호**, 각각 몇 초. URDF는 네 소비자(ros2_control, RSP, MoveIt, RViz)의 단일 입력이라 실수 하나가 무관해 보이는 에러 넷 | ✗ |
| 6 | 충돌 기하 단순화 + SRDF allowed-collision matrix | 플래너가 μs 단위로 상태 평가, 인접 링크 접촉이 충돌로 안 읽힘 | ○ 플래너 안 쓰면 (대신 런타임 충돌 검사 0 — z바닥 체크가 전부를 떠안음) |
| 7 | **로봇 없이 기구학 + 테스트** — FK→IK→FK **포즈 공간** 왕복, 작업공간 샘플링, 경로 따라 분기 연속성 | 수학이 ROS·HW·타이밍·전송과 독립적으로 맞음 → 팔이 엉뚱한 데 가면 후보가 하나 남음 | 테스트는 ✗ (절대 관절각으로 학습하면 IK 자체가 불필요) |
| 8 | **mock hardware 위 전체 그래프** — xacro 인자로 `mock_components/GenericSystem`, 내 노드까지 전부 | 제어기 활성화, YAML↔URDF 관절명(“failed to activate” 1위 원인), 궤적 수락, 리맵, TF 폐합. **통합 버그 ~70%를 위험 0으로** | ✗ **가장 흔히 건너뛰는 단계** |
| 9 | 물리 시뮬 (Gazebo Harmonic / MuJoCo), `use_sim_time:=true` | 접촉, 중력 처짐, 경로가 테이블을 관통 안 함 | ○ 모방학습 캡스톤이면 (버스 타이밍·서보 PID·스틱션·백래시·카메라 노출은 어차피 재현 불가, URDF effort=1000이면 없는 로봇을 시뮬) |
| 10 | **첫 하드웨어 세션을 사다리로** — 열거 → 읽기 전용 스캔 → **토크 끄고 손으로 밀며** 값 확인 → 무해한 쓰기 → 한 관절 +2° → 전체 소진폭 | 각 칸이 하나씩: 버스 / ID맵+변환(공짜로 동시에) / 쓰기 경로 / 닫힌 루프 하나 / 반이중에 여섯 공존 | 압축 가능, **순서 변경 불가** |
| 11 | **버스를 ros2_control에 넘기고 아래→위 확인, 그리고 hold** — HW active → 제어기 active → `/joint_states` ~100 Hz → 손으로 밀면 tf2_echo 변화 → **지금 자세를 그대로 명령** | 포트 단일 소유 + 설정 멱등성. hold가 관절 순서·단위·프레임·리맵·체인 전체를 증명, **정답은 "아무 일도 안 일어남"** | ✗ (움찔하면 0 rad/s에서 배운 것) |
| 12 | **액션으로 호밍 → 리미터 켜기** — 실제 `<limit>`, `<safety_controller>`, `enforce_command_limits`, JTC `cmd_timeout`/goal_time, **Bus Watchdog(98) ~100 ms** | 명령 경로가 *수락*이 아니라 *완료*를 보고. 나쁜 명령은 프레임워크가 막고 죽은 호스트는 **펌웨어가** 잡음 | △ 대부분 학생 프로젝트가 여기서 멈춤 (position 모드 DXL은 프로세스가 죽어도 마지막 목표를 영원히 유지) |
| 13 | **강제된 순서의 캘리브레이션** — 관절 0점 → 중력/마찰 → 카메라 내부 → hand-eye | 취향 아님: 일정한 관절 오프셋은 **자세에 따라 변하는 팁 오차**로 전파돼 오프셋처럼 안 보임. hand-eye(AX=XB)는 내부값으로 B를 계산 → 나쁜 내부값이면 **자신만만하게 수렴한 완전히 틀린 변환**. 강체 마운트 1–3 mm, 휘는 3D프린트 브래킷은 바닥이 생김 | 부분 ○ |
| 14 | **텔레오퍼레이션 → 시간 동기 측정 → 그다음 기록** | 태스크가 물리적으로 가능, **데이터셋에 체계적 거짓말 없음.** 텔레오퍼레이션이 **행동 공간을 정의** (리더가 내는 것 = 정책이 배울 출력) | ✗ (40 ms 스텝에 카메라 50 ms 지연 = 모든 에피소드에 한 스텝 이상의 회복 불가 오차, 나중에 "데이터가 더 필요"로 나타남) |
| 15 | **안전 게이트 뒤 정책 노드, 더미 모델 먼저** — 게이트: **각도 아닌 속도**, IK 가능성, 작업공간 바닥, NaN/inf, `/joint_states` 신선도. **거부하고 유지, 절대 클램프 금지** | 배포 경로가 모델 품질과 독립적으로 맞음 → 정책이 못하면 정책 탓 | 더미 단계가 핵심 (클램프된 행동 = 정책이 고르지 않은 행동을 본 적 없는 상태에서 실행 = 분포 이동) |
| 16 | CI + **차가운 컨테이너 재현** + 실행 스탬프 (git SHA, 이미지 digest, `.repos` export, **서보 컨트롤 테이블 덤프**) | 문서화 안 된 수동 단계가 없음 | CI는 △, 차가운 재현·스탬프는 ✗ (RAM 레지스터는 전원 사이클에 리셋 — 덤프해두지 않으면 실제 설정을 복원 불가) |

## 우리가 어디서 넘어졌나 (9/8–9/17)

**7단계(기구학·테스트)와 15단계(더미 정책·게이트)는 잘 했고, 2·3·4·8단계를 건너뛰었다.**
그 주에 겪은 문제는 전부 건너뛴 네 단계에서 나왔다:

| 겪은 일 | 빠진 단계 |
|---|---|
| 노드가 안 보임, `/joint_states` 무한 대기 | **2** — 전송 배관, zenoh 라우터 |
| 팀원 프로세스와 포트 충돌, 반복 세그폴트 | **3** — 버스 소유 규칙 |
| 관절 한계값이 세 출처에서 불일치 (데이터시트 / URDF ±2π / xacro tick) | **4** — 한계값 출처를 하나로 |
| 실기에서 모든 걸 한꺼번에 디버깅 | **8** — mock hardware |

위층은 튼튼했고 발판이 없었다. `dxl_basics`로 하는 건 사실 **4단계와 10단계**다.

## 학습 정책이면 달라지는 것

1. **플래너가 사라진다.** MoveIt이 주던 도달성·자기충돌·장애물 회피를 전부 직접 빚진다.
2. **지능이 오프라인으로 간다.** 학습은 로봇과 끊긴 배치 작업 — "팔이 바보짓" → "안 함"까지 몇 시간. 이게 모방학습 프로젝트 관리의 결정적 사실.
3. **정책은 실행 불가능을 보고할 수 없다.** 플래너는 "해 없음", 정책은 **자신만만하고 형식 완벽한 물리적으로 미친 벡터**(테이블 40 cm 아래, 40 ms에 170° 손목 회전)를 대역 내 신호 없이 반환. 모든 검사를 명시적 게이트로 재구축해야 함.
4. **새 구성요소: 속도 브리징 chunk 실행기.** 추론 5–15 Hz ↔ 제어 100 Hz. 하드 데드라인이 있는 진짜 제어 부품이고 **모방학습 버그는 사실상 전부 여기 산다.**
5. **액션/토픽 선택이 뒤집힌다.** 호밍은 액션, 정책은 토픽.
6. **JTC 세부가 하중을 받는다.** velocity 없으면 선형 보간(매 웨이포인트 속도 계단), 마지막 점 velocity≠0이면 전체 거부 → **실행하는 것보다 멀리 publish**해서 필수 zero-velocity 꼬리를 리플랜 지점 너머에 둔다.
7. **행동 표현은 한 번 고르면 되돌리기가 가장 비싸다(데이터셋 무효).** 절대 관절각 = 런타임 기구학 없음·다른 팔 이식 불가. 상대 SE(3)(UMI) = 하드웨어 독립·IK 분기 전환을 불연속 후보로 상속. 회전은 연속 6D → Gram-Schmidt (쿼터니언 이중피복, 오일러 wrap 회피).
8. **시간 동기가 서브시스템이 된다.** 카메라·관절 버스·정책 타이머는 세 개의 독립 시계. UMI는 지연 네 개를 네 방법으로 재고 각 액션을 절대 시각 − 액추에이터 지연으로 스케줄.
9. **데이터셋이 명세를 대체한다.** 유일한 명세는 고정 리셋 프로토콜 하의 N회 성공률. 50% 정책도 8번에 1번은 3연속 성공 → 일화는 무가치, **평가 하네스는 인프라**.
10. **그리퍼가 별도 장치가 아니다.** AI 설정은 `gripper_joint_1`을 arm_controller에 합침 — 정책은 타임스텝당 6-벡터 하나를 내므로.
11. **설정은 플래그가 아니라 메타데이터에.** fps·정규화 통계·피처 스키마가 체크포인트와 함께 다녀야 한다. 학습/배포 정규화가 다르면 쓰레기가 나오는데 스택은 아무 말도 안 한다.
12. **이 커뮤니티 상당수는 ROS를 버린다.** UMI·Diffusion Policy·LeRobot 코어는 파이썬 멀티프로세싱 + 공유메모리 링버퍼. 잃는 것(TF, RViz, rosbag, MoveIt, ros2_control 한계 강제·lifecycle)은 형편없이 재구현되거나 아예 없다.

## 초심자 함정 (우리가 이미 밟았거나 밟을 것 위주)

| 함정 | 올바른 습관 |
|---|---|
| mock 건너뛰고 URDF → 실기 직행 | `use_mock_hardware:=true`가 두 번째로 돌리는 것. 그래프가 mock에서 전부 초록일 때까지 실기 대기 |
| URDF의 한계값을 믿음 (`±2π, velocity 4.8, effort 1000` 여섯 개 = 아무도 안 채운 플레이스홀더) | 레지스터를 읽고 URDF를 거기에 맞추고, 나머지 출처를 그 표에서 생성 |
| 의미를 주는 모드를 안 보고 레지스터를 읽음 | Operating Mode, Drive Mode 먼저 덤프 — 나머지 단위가 거기 달렸다 (Drive Mode bit2=시간 기반이면 Profile Velocity 50 = 50 **ms**) |
| 위치를 읽기 전에 토크 ON | RAM의 옛 Goal Position으로 튄다. `Goal := Present` → 확인 → ON. 뻗은 팔은 절대 토크 사이클 금지 |
| "잠깐 확인만" 두 번째 프로세스로 포트 열기 | `sudo fuser -v /dev/ttyACM0`, `docker ps`가 **내 코드 읽기 전 첫 두 명령** |
| 리셋된 RAM 레지스터를 별도 SDK 스크립트로 "고침" | 그 스크립트가 두 번째 버스 소유자. 값은 매 활성화 때 다시 주입되는 곳(`<gpio>` / 초기화 테이블)에 |
| 빈 `ros2 node list`를 코드 버그로 취급 | 미들웨어부터: 라우터, RMW, DOMAIN_ID |
| `ros2 topic echo`에 나오니 내 구독자도 될 거라 생각 | CLI는 관대하게 구독. QoS 불일치는 조용하다 → `--verbose` |
| 덜컹거림을 제어율 올려서 해결 | 어느 층이 대역폭 한계인지 먼저. 여기선 서보 프로파일 생성기, 손잡이는 Profile Velocity |
| velocity 없이 position만 보내고 하드웨어 탓 | 중앙차분 velocity, 마지막 점 0 |
| 10 ms마다 단일점 궤적 publish로 100 Hz "맞추기" | 보간기와 싸우는 것. 실제 duration 있는 세그먼트를 보내고 JTC가 일하게 |
| 스텝당 **각도**로 정책 게이트 | 같은 6°도 time_scale에 따라 순하거나 폭력적. `|Δq|/Δt`를 rad/s로 |
| 위험한 행동을 **클램프** | 거부하고 유지하고, 어느 스텝·어느 숫자인지 로그 |
| 읽은 상태가 현재라고 가정 | `is_async`면 최소 한 사이클 + 전송 + USB = 현실적으로 15–30 ms. 마지막 JointState가 ~100 ms 넘게 낡으면 publish 중단 |
| 런치 로그·spawner 종료코드를 믿음 | `ros2 control list_controllers` → `list_hardware_interfaces` → JTC 로그, 15초 |
| 코드 읽고 추론으로 디버깅 | rqt_graph → `ros2 topic hz` → list_controllers → tf2_echo → PlotJuggler(명령 vs 실측). 싼 것부터, 읽은 값이 놀라우면 추측 중단 |
| 두 개를 동시에 바꾸고 첫 성공을 믿음 | 실행당 변수 하나, 적어두고 bag 파일명 옆에. 정책 주장은 고정 리셋 20회 이상 |

## 정직한 유보 (조사자들이 합의 못 했거나 근거가 얇은 것)

- **ros2_control을 유지할 가치는 실제로 논쟁 중.** 이 팔에서 유지할 정직한 이유는 MoveIt·RViz·벤더 텔레오퍼레이션 장비지 결정성이 아니라는 의견. `GroupSyncRead/Write` 파이썬 루프는 비동기 USB 컴포넌트와 최악 지터가 비슷. 버리면 아픈 순서: MoveIt → 토픽 관측 경로(RViz·rosbag) → JTC 스플라인 → 초기화 레지스터 주입 → **포트 배타성**.
- **절대 관절각 vs 상대 SE(3)**: 캡스톤이면 절대 관절각을 권하는 의견 ("요점이 UMI식 cross-embodiment가 아니라면"). 그 경우 해석적 기구학은 교육적이지만 선택적. 다른 의견은 상대 표현이 UMI의 정의 자체. **되돌리기 가장 비싼 결정.**
- **chunk 경계 덜컹임에 대한 두 답**: receding horizon(UMI/DP, Ta=8 최적) vs ACT temporal ensembling(매 스텝 질의 후 지수평균 — 52M 파라미터·~5 ms라서 가능). LeRobot은 `temporal_ensemble_coeff`와 `n_action_steps>1`을 같이 쓰면 에러.
- **버스 산술(1.78 ms/562 Hz)과 서보 ~1 kHz는 계산·추정**, ROBOTIS 비공개. 실제 천장은 USB. **측정할 것.**
- **충돌 층**: MoveIt PlanningScene에 테이블 모델링 ≈ 1주 + 아키텍처 변경(MoveIt은 계획하지 스트리밍 안 함) / 기존 FCL 캡슐 노드에 테이블 반공간 추가 ≈ 1일 / 게이트의 z바닥 체크로 실용적 이득 대부분.
- **시간 동기**: 벤더 physical_ai_server는 `ApproximateTimeSynchronizer`를 안 쓰고 토픽별 최신값을 덮어씀. "실용적이지만 옳지는 않은" 선택 — 학습된 정책이 자기 텔레오퍼레이션보다 못하면 가장 먼저 계측할 곳.
- **e-stop 비용**: 브레이크 없는 팔은 전원을 끊으면 **떨어진다**(335 g이 joint2 위). 그래도 설치 만장일치 + "아끼는 물건 위로 팔을 뻗지 않는다" 규칙과 짝. 서보 과부하 셧다운도 같은 비대칭 — 모터는 보호하지만 팔 입장에선 최악의 순간의 무명령 토크 해제.
- **ID 11–16 ↔ joint1–5+gripper 매핑은 xacro `<gpio>` 순서에서 추론**, 어디에도 글로 없음 → 10단계(토크 끄고 손으로)로 확인하기 전엔 믿지 말 것.
- 이 Jetson + OpenRB-150 + rmw_zenoh 조합의 지연 수치(첫 동작 15–25 ms, 정착 65–80 ms)는 부품 수치로 **추산**, 실측 아님.
