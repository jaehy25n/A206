# 01. 기본기와 첫걸음

## 기본기 네 개

로봇이 바뀌어도, 프레임워크가 바뀌어도 남는 것.

### 1. 좌표계와 변환
로봇공학의 거의 모든 질문은 *"A를 기준으로 B가 어디 있는가"* 다.
관절각 → 그리퍼 위치도, 카메라가 본 물체 → 팔이 갈 좌표도 전부 이것.
동차변환 행렬 `[R p; 0 1]` 하나를 손으로 곱할 수 있으면 TF, FK, hand-eye 캘리브레이션은 같은 것의 변주다.

### 2. 읽기가 쓰기보다 먼저다. 그리고 관측은 항상 과거다
제어 = "지금 어디 있나 → 어디 있어야 하나 → 차이만큼".
첫 항이 없으면 나머지는 의미가 없다. 그리고 읽은 값은 이미 몇 ms 낡았다 — 그 지연이 곧 오차다.
(1 rad/s로 움직이는 중에 20 ms 낡은 값이면 이미 1.1° 오차)

### 3. 경계마다 단위와 주기
층 사이로 **무엇이, 어떤 단위로, 얼마나 자주** 넘어가는가.
버그 대부분은 층 안이 아니라 경계에 있다 — tick인가 rad인가, ms인가 rpm인가, 절대인가 상대인가.

### 4. 위가 멈추거나 거짓말하면 아래가 뭘 하는가
정상 동작은 쉽다. 설계의 실체는 실패 경로다.
프로세스가 죽으면 팔이 멈추나 떨어지나? 명령이 말이 안 되면 거부하나 잘라내나?

> ROS, ros2_control, MoveIt, 도커는 전부 **도구**다. 위 네 개를 아는 사람에게는 편의고, 모르는 사람에게는 이해 못 할 마법이다.

## 첫 번째로 할 일 — 딱 하나

> **토크를 끄고, 손으로 팔을 움직이면서, 화면의 숫자 여섯 개가 따라 움직이는 걸 본다.**

시시해 보이지만 한 번에 증명하는 것:

- 전원·배선·시리얼이 살아 있다
- **ID 11~16이 어느 관절인지** — 문서 어디에도 글로 안 적혀 있다. 벤더 xacro의 `<gpio>` 블록 **순서**에서 추론한 것뿐. joint2를 밀었을 때 12번이 움직이면 그 순간 확정
- **tick ↔ 각도 변환** — 눈대중 직각으로 꺾어서 raw가 ~1024 변하면 4096/회전이 맞다
- **부호** — 위로 올렸는데 각도가 줄면 그 관절은 부호가 반대. IK에서 잡기 가장 어려운 종류의 버그가 여기선 5초
- 위험 0 (쓰는 게 토크 해제뿐)

### 필요한 레지스터 네 개

| | 주소 | 크기 | 비고 |
|---|---|---|---|
| Torque Enable | 64 | 1 B | 0 = 모터 해제 (RAM) |
| Present Position | 132 | 4 B signed | |
| Homing Offset | 20 | 4 B signed | 서보가 어디를 0이라 부르는지 (EEPROM) |
| Operating Mode | 11 | 1 B | 3 = position, 4 = extended position |

루프: `읽기 → 화면 → 0.1초 쉬고 → 반복`. 30줄이면 된다.
이미 만들어 둔 것: [`prototypes/dxl_basics/s3_watch.py`](../../prototypes/dxl_basics/s3_watch.py) (움직이는 줄에 `<-- moving` 표시, 시작점 대비 이동량 표시).

### 실행 전 세 가지

1. **포트를 아무도 안 잡고 있어야 한다.** 선이 한 가닥(반이중)이라 두 프로세스가 동시에 열면 에러 없이 바이트가 섞인다.
   증상은 "port busy"가 아니라 **간헐적 CRC 오류·유령 타임아웃**.
   ```bash
   sudo fuser -v /dev/ttyACM0; docker ps
   # 뭔가 잡고 있으면 (컨테이너 s6가 부팅 때 브링업을 자동으로 띄웠을 수 있음)
   docker exec open_manipulator bash -c "pkill -f '[r]os2_control_node'; pkill -f '[r]os2 launch'; pkill -f '[s]pawner'; sleep 3"
   ```
2. **포트 권한** — `/dev/ttyACM0`은 보통 `root:dialout`. 그룹에 없으면 `sudo python3 ...` (그룹 추가는 시스템에 영구히 남으니 굳이)
3. **팔을 접어놓는다** — 브레이크가 없고 560 g 중 약 335 g이 joint2 위에 있다. 토크를 끄면 늘어진다. 접은 자세로, 손으로 받치고.

### 실행

```powershell
# Windows PowerShell (저장소 루트에서)
scp prototypes\dxl_basics\*.py <user>@<jetson-ip>:~/dxl_basics/
```
```bash
# 오린 — 컨테이너·ROS·pip 불필요, 시스템 python3로 충분
cd ~/dxl_basics && python3 s3_watch.py --port /dev/ttyACM0               # 1) 읽기만
cd ~/dxl_basics && python3 s3_watch.py --port /dev/ttyACM0 --torque-off  # 2) yes 입력 후 손으로
```

- 1)에서 볼 것: `homing off` 열이 **0이 아니면**, 그게 "joint3이 98.79°인데 xacro는 96°" 미스터리의 유력한 정답. 읽을 수 없는 C++에 숨어 있다고 생각한 캘리브레이션이 레지스터 하나였던 것
- 2)에서: 쓴 값을 **다시 읽어서 확인**한다 (확인 안 한 쓰기는 믿지 않는다)
- 끝나면 Ctrl-C. **토크는 꺼진 채로 남는다.** 다시 켜는 건 순서를 지켜서 — 무턱대고 켜면 RAM에 남은 옛 Goal Position으로 튄다 (`Goal := Present` 후 Torque ON)

> `dxl_basics`에는 `Dockerfile` + `run.sh`(python:3.12-slim + pyserial, `--rm`)로 컨테이너에서 돌리는 경로도 있다.
> 둘 다 같은 `/dev/ttyACM0`을 연다 — 컨테이너는 디바이스를 격리하지 않는다. 단, 컨테이너 경로는 pyserial이 있어서
> `dxl_raw.py`의 termios 백엔드는 실행되지 않는다(호스트에서 pyserial 없이 돌려야 그 경로가 검증됨).

## 그다음 세 단계

| # | 할 일 | 증명하는 것 |
|---|---|---|
| 2 | 읽은 각도로 FK 계산 → 그리퍼 위치를 **자로 재서** 대조 | 기본기 1번이 실물이 됨. 계산 22 cm인데 실측 19 cm면 링크 길이 or 각도 변환이 틀림. 건너뛰면 나중에 원인 후보가 다섯 개 |
| 3 | **한 관절만 2°** (전원 스위치에 손가락) | 쓰기 경로 전체. 2°가 되면 10°도 되고, 안 되면 문제는 기구학이 아니라 쓰기 경로 |
| 4 | 여섯 개 동시에, 한 점으로 | 처음으로 IK가 필요. 반이중 버스에 여섯 개 공존도 처음 시험 |

원칙: **읽기 전에 쓰지 않기 → 동작 전에 무해한 쓰기 → 여섯 개 전에 한 개 → 큰 것 전에 작은 것.** 압축은 돼도 순서는 못 바꾼다.

## 기존 코드에 대해

**개념은 남기고, 코드는 다시 쓴다.** [`prototypes/dummy_pipeline/omx_kinematics.py`](../../prototypes/dummy_pipeline/omx_kinematics.py)의 링크 길이·변환은 URDF에서 나온 진짜 숫자라 참고 가치가 있다.
하지만 읽어서 왜 그런지 설명할 수 없는 줄은 쓰지 않는다. 특히 IK는 직접 유도 — 5자유도 팔에서 yaw가 왜 자유롭지 않은지(`yaw = atan2(y, x − BASE_X)`로 강제됨)를 손으로 깨닫는 게 코드를 열 번 읽는 것보다 낫다.
